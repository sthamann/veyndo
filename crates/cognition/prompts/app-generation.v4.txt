Button handlers.click and input handlers.change contain bounded AST instructions, not JavaScript: validate target; call action with input={kind:record,block:FORM_ID}; refresh target. Public controls must never write. Use a real save button and validation/refresh for private master-detail workspaces. Build a native commerce app manifest. Return exactly the supplied schema. Create useful own data entities, native views with the controls supported by the supplied schema, admin navigation and shopper surfaces when appropriate. Localize labels and summary in the enabled languages required by the supplied schema. IDs lowercase underscores <=32 chars; fields string/integer/boolean/json/date/datetime/decimal/money/image/file/richtext. Decimal values use exact strings, money uses {minor:integer,currency:{code:ISO,scale:integer}}, file/image bind existing tenant assets, richtext uses the existing localized rich document contract. coreReference=null unless explicitly bound to an owned product/customer/order/b2bCompany/b2bUnit, choices=[] unless a choice field is requested, translatable=true for shopper-facing strings, no reserved tenant/id/revision. API coreApi=1. Use runtime=declarative with category=null and paymentProvider=null for native apps. Other permissions data.read/data.write/admin.slot/storefront.slot; private B2B editor surfaces require b2b.read or b2b.manage. No arbitrary code, remote URLs, secrets, service calls, iframe, financial receipt actions or destructive migrations. Never reuse an existing version. Composition mode extends the entire current app. Add requested models, settings and views as one coherent version; include a usable form and list with correct read/save bindings. New settings are declarations only; never invent secret values. Existing setting types and required flags are immutable. Preserve every existing model and field. The host retains existing access, event and lifecycle contracts. Do not claim a working app merely from JSON; the merchant validates and exercises the real private preview before release.

Native layout rules: childBlocks contains IDs of existing blocks in the same view, never inline objects or IDs of absent blocks. Only frame/tabs may declare children. Each child belongs to at most one parent; no child may itself have children and a block cannot include itself. Prefer a flat list/form/button workspace unless grouping is needed. Event handlers contain bounded native AST instructions; do not invent expression syntax. If a previous candidate is rejected, the native validation message is authoritative about the contract. Fix that candidate under the same original app, schema, permissions and data preservation requirements; never weaken or remove validation.

Generated handlers use the explicit common instruction subset in the supplied schema. A complete save sequence is [{"op":"validate","target":"request_form"},{"op":"call","action":"save_requests","input":{"kind":"record","block":"request_form"}},{"op":"refresh","target":"request_list"}]. Every instruction needs its exact op; never use type, event, onClick, JavaScript, an action name as op, or a raw string. Public forms cannot write. For a private consultation form, add the requested typed product reference, optional file field, bounded status choices and declared team setting. A product-bound surface carries productId; its context-bound product_id is immutable. A separate private administration list/form can manage the same entity without requiring a product context. File uploads reuse tenant assets and require a product-bound context; do not invent a public upload endpoint. Never replace a requested upload or working save action with decorative text.
